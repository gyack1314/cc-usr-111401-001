# 可恢复阶段交换协议

`warehouse/stage.py` 在既有 Exchange（run 为执行代、`(run, side, partition, fragment)`
为片段身份的本地通道）之上，为查询运行层提供跨下游进程重启的阶段交换。这里只
处理查询中间数据，不做数据源采集。调度由调用者显式驱动（`Coordinator.step` /
`run`），不依赖墙钟 sleep。

## 通道、序号与完成标记

- 生产通道为 `(run, side, partition)`；通道内序号从 0 连续递增，片段身份即其
  起始序号 `first_seq`，片段覆盖 `first_seq .. first_seq+len-1`。
- 完成标记 `complete(side, partition, last_seq)` 给出最后一个序号，空通道为 -1；
  各通道完成到达顺序可以任意。完成标记重复且一致时幂等，冲突则判查询已失败。
- 重复传送按逻辑身份去重：内容一致返回 `duplicate`，内容冲突判失败；序号已
  消费的片段返回 `consumed` 直接丢弃，不重复交付。
- 交付严格按各通道序号顺序；缺口处停住，完成标记不能掩盖缺口。

## 屏障、恢复点与确认

1. 协调者 `issue_barrier()` 单调发出屏障编号，记录各通道目标位置（cuts）。
2. 当所有通道消费位置越过 cuts，屏障对齐：下游执行替身快照状态，按屏障编号
   登记状态摘要（`run|barrier|<n>`），随后写入恢复点。
3. 恢复点（`run|checkpoint`）同时包含：执行代、屏障编号、**各通道**消费位置
   与完成标记（不是全局最大序号）、仍需保留的在途片段清单（身份、摘要、字节
   数）、下游状态（分片数、状态对象摘要、各分片摘要）以及计量快照。
4. 恢复点落盘后，协调者按通道 `ack(generation, side, partition, upto)` 确认；
   交换层回收确认位置以下的全部片段（回执、元数据、内容对象按引用计数删除）。

## 执行代隔离与重新分配

- 每次启动（含重启）`begin_generation()` 单调递增并持久化执行代；确认、检查点
  与回收只接受当前持久代，旧代调用记录 `stale_ack` 并拒绝。
- 旧协调者一旦察觉代过期即被隔离，其执行替身被 fence，不能再处理行。
- 重启可以改变消费分片数：下游状态以类型化键的整体映射快照，恢复时按新分片
  数重新哈希分配；旧代工作者无法确认或回收新代所需片段。

## 背压与溢写

- 片段接收即经既有 Exchange 持久化；内存只作缓存，超出 `memory_budget` 的片段
  记为溢写（`spill`），交付时按需重载（`reload`）。
- 未消费在途字节受 `pending_budget` 约束：覆盖消费位置的片段总是接受（避免与
  缺口互相等待造成死锁），其余前瞻片段在预算不足时被限流（`throttle`），不会
  为等待最慢通道而无界缓存。

## 状态分类

- `incomplete`（尚未完成）：运行中或仍有缺口/未登记完成。
- `recoverable`（可以恢复）：重启后恢复点与在途片段校验一致，可继续。
- `failed`（查询已失败）：片段内容冲突、完成标记矛盾、恢复点保留片段丢失或
  损坏等不可恢复情形。
- `complete`：全部已登记通道交付越过完成标记且最终恢复点已固化。

## 调度日志与核对

所有事件（提交、去重、溢写、重载、限流、交付、屏障、检查点、确认、回收、
失败、代更替）追加写入 `journal.jsonl` 并同步落盘。`audit(path)` 重放日志，
给出每条逻辑行 `(channel, seq)` 的交付历史（代、分片）与有效交付，区分回滚
重交与覆盖交付，并校验：同代不重复交付、交付不低于恢复位置、回收必有覆盖
检查点且不在其保留清单、完成通道不缺行。日志同时留下缓存、溢写与回收的实际
计量（字节与片段数）。
